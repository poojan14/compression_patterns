Part A · Image Compression

1. Why image compression?

Image compression reduces the redundancy in how an image is represented, so it needs less storage and bandwidth, ideally without a visible loss of quality.

Transmission

Raw images need huge bandwidth, causing latency and congestion. Smaller files mean faster upload and download, smooth streaming and real-time video calls.

Storage cost

Local and cloud storage cost money. Reducing data size directly reduces that cost.

Processing

Edge detection, filtering and recognition run faster on smaller or compressed representations, needing less hardware.

Measuring compression

If the original needs n₁ bits and the compressed version needs n₂ bits:

  • Compression ratio CR = n₁ / n₂ (for example 10:1)
  • Relative data redundancy R = 1 − 1/CR (the fraction of the original data that was redundant)
  • Percent reduction = (n₁ − n₂) / n₁ × 100 (equal to R × 100)
  • Compressed payload = (1/CR) × 100% of the original size

2.1 Coding redundancy

A code is a set of symbols used to represent information; each piece of information gets a code word, and its length is the number of symbols in it. If an 8-bit image uses all 8 bits for every gray level, a very common gray level costs as much as a rare one. Giving shorter code words to more probable values removes this waste. See Huffman (Section 6).

2.2 Interpixel redundancy and predictive coding (DPCM)

Because neighbouring pixels are similar, DPCM sends the prediction error e = x − x̂ instead of the pixel itself. Here the prediction x̂ is simply the previous pixel. The errors cluster near 0, so their entropy is much lower and a variable-length coder needs fewer bits. The decoder adds each error back to its own prediction, so the process is lossless.

On a whole image

2.3 Psychovisual redundancy and quantization

The eye is much less sensitive to fine, high-frequency detail and to colour detail than to brightness. Information it cannot perceive is wasted space. Removing it is the only way to exploit this redundancy, so it is always lossy.

Quantization throws that detail away by mapping a whole range of values to one representative value: q = round(value / step), and the decoder reconstructs value' = q × step.

2.4 Psychovisual redundancy and chroma subsampling

Colour images are converted from RGB to YCbCr: Y is brightness (luma), Cb and Cr are colour differences (chroma). Because the eye resolves colour detail poorly, the chroma planes can be stored at lower resolution. This is chroma subsampling, and it is lossy.

Y = 0.299R + 0.587G + 0.114B · Cb = 128 − 0.1687R − 0.3313G + 0.5B · Cr = 128 + 0.5R − 0.4187G − 0.0813B

Why is there no "inverse quantizer" in the decoder model?

Quantization is many-to-one. With step 16, every value from 136 to 151 becomes q = 9 (try it in Section 2.3), and the decoder can only output 9 × 16 = 144. Nothing in the stored "9" says whether the original was 136 or 151, so no function can undo it. The other blocks are one-to-one: zigzag only reorders, RLE and Huffman codes decode to exactly one sequence, the DCT is an invertible linear transform, and RGB ↔ YCbCr is an invertible change of coordinates.

Precise wording. A JPEG decoder does contain a dequantizer that multiplies by the step size. It is a reconstruction (an estimate), not a true inverse; the difference is the quantization error. Also, the quantizer is the main lossy step but not the only one: chroma subsampling also discards data, and the decoder can only interpolate it back.

5. Run-Length Encoding (RLE)

A run is a sequence of consecutive, identical values. RLE stores each run as a single value plus its count. It is lossless and works best when there are long runs, as in binary (black-and-white) images, scanned documents and simple graphics.

6. Huffman coding

  
A lossless, variable-length code: more frequent symbols get shorter codes. It removes coding redundancy and is optimal among codes that assign a whole number of bits to each symbol.

  
Building the tree

  
    
    
  1. Put every symbol in a min-heap (priority queue) keyed by frequency.
    2. 
    
  2. Pop the two smallest nodes and join them under a new node whose frequency is their sum. The first popped (smaller) becomes the left child, edge 0; the second becomes the right child, edge 1.
    3. 
    
  3. Push the new node back; it can be popped and merged later like any other node.
    4. 
    
  4. Repeat until one node remains: the root. Each code is the sequence of 0s and 1s on the path from the root to the leaf.
    5. 
  

  
Ties are broken in the order the symbols are listed (original symbols before newly created nodes). A different tie order can give different codes with the same total length.

8. Transform coding: DCT and DWT

  
Transform coding is a mapper: it moves the image into a frequency domain where most energy sits in a few coefficients. The transform itself is reversible; compression comes from quantizing or discarding the many small coefficients afterwards.


  
8.1 Discrete Cosine Transform (DCT)

  
The 8×8 DCT writes every block as a weighted sum of 64 cosine patterns (basis images). F(0,0) is the DC term (block average); patterns further right or down have higher horizontal or vertical frequency. Click a pattern to enlarge it.

8.2 Discrete Wavelet Transform (DWT)

  
The DWT uses multi-resolution analysis: low-pass and high-pass filters are applied along rows and then columns, splitting the image into four sub-bands. The LL band is a half-size approximation and is decomposed again for the next level. JPEG 2000 uses the DWT on the whole image instead of block DCT, so it has no 8×8 blocking artifacts. This demo uses the simple Haar wavelet.

  

  

    
  

  

    
    
  

  

  
Layout: LL top-left, HL top-right (vertical edges), LH bottom-left (horizontal edges), HH bottom-right (diagonal detail). Textbooks differ in which of HL and LH they call "horizontal".

11. Decision-theoretic methods

  
We want W decision functions d₁(x), …, d_W(x). An unknown pattern x belongs to class ωi if
  dᵢ(x) > dⱼ(x) for every j ≠ i. In words: substitute x into every decision function, and the largest value wins.

  
The decision boundary between classes i and j is where dᵢⱼ(x) = dᵢ(x) − dⱼ(x) = 0. Patterns of ωi give dᵢⱼ(x) > 0 and patterns of ωj give dᵢⱼ(x) < 0.


  
11.1 Matching: minimum-distance classifier

  
Each class is represented by a prototype mj (the mean of its training patterns). The unknown is assigned to the nearest prototype using Euclidean distance D = √Σ(xᵢ − yᵢ)².
  This is the same as using the decision function dⱼ(x) = xᵀmⱼ − ½ mⱼᵀmⱼ and taking the largest.

  
Try it: click or tap anywhere on the plot to place an unknown flower. The coloured background shows which class every point would be given; the borders between colours are the decision boundaries (perpendicular bisectors between prototypes).

  
  

  

    
  

  

    
    
  

  

  
Limitations of template matching: the object must be well segmented, results are sensitive to lighting and background clutter, and performance drops sharply with occlusion, rotation and scale changes.


  
11.2 Optimal statistical (Bayes) classifier

  
Image data is uncertain (lighting, occlusion, viewpoint), so we use probabilities. Bayes' theorem gives the posterior probability
  P(ωᵢ|x) = p(x|ωᵢ) P(ωᵢ) / p(x). Assign x to the class with the largest posterior. This gives the minimum probability of error on average.

  
Since p(x) is the same for every class, the Bayes decision function is simply dⱼ(x) = p(x|ωⱼ) P(ωⱼ). For 1-D Gaussian classes:
  dⱼ(x) = (1 / √(2π) σⱼ) · e−(x − mⱼ)² / 2σⱼ² · P(ωⱼ).

  
Try it: move the sliders. Watch the boundary (where the two curves cross) shift when you change a prior or a spread.

  
  

    
    
    
    
    
    
  

  

  
Application: classifying a multispectral aerial image into vegetation, water and bare soil. Each pixel is a pattern vector of its brightness in several spectral bands, and a Gaussian Bayes classifier labels every pixel.







  
12. Neural networks

  
A neural network is made of neurons in layers: an input layer, one or more hidden layers, and an output layer. Training (learning) uses a training set to find the weights, which together form the decision function. Instead of hand-designing features, a deep network learns a hierarchical non-linear function f(I) that maps an image I to class probabilities. The final decision picks the class with the maximum posterior probability.

  
History: interest began in the 1940s. In the 1950s and 1960s Rosenblatt proposed the perceptron as a learning machine.


  
12.1 Perceptron (Rosenblatt)

  
One neuron: multiply each input by a weight, add them, and compare with a threshold T.
  y = Σ xᵢwᵢ, output = 1 if y > T, else 0. Its decision boundary w₁x₁ + w₂x₂ = T is a straight line, so it can only separate linearly separable classes.

  
Try it: pick a problem, then press Train. The learning rule is w ← w + η(t − o)x and T ← T − η(t − o), with η = 0.1. AND and OR converge. XOR never does.

12.3 Multilayer perceptron (MLP)

  
An MLP (feedforward network) stacks layers of perceptrons. The hidden layers let it learn non-linear boundaries, so it can solve problems like XOR that a single perceptron cannot. A classic example recognises four shapes using an input pattern vector, layer A with 48 neurons, layer B with 26 neurons, and an output layer Q with 4 neurons, one per shape.

  
  
Every neuron connects to every neuron in the next layer. Training (back-propagation) adjusts the weights wba and wqb.


  
12.4 Convolutional neural network (CNN)

  
CNNs are neural networks designed for images. Typical flow: convolution → ReLU → pooling → (repeat) → fully connected → class scores (dog / cat / lion / bird).

  

    
Convolution layer
Moves small filters (kernels) across the input. Each filter produces a feature map showing where its feature (edge, texture, …) appears. Does most of the computation.

    
Pooling layer
Max or average over small windows. Shrinks width and height, reduces computation, and helps control overfitting.

    
Fully connected
Flattens the final feature maps and maps them to class scores, usually with softmax at the end.

14. Structural methods

  
Structural methods use the relationships inherent in a pattern's shape rather than numbers alone. Three methods: syntactic recognition of strings, matching shape numbers, and string matching.


  
14.1 Syntactic recognition of strings

  
Three ingredients: (1) a set of pattern primitives, (2) a grammar of rules for how they connect, and (3) a recognizer (automaton) built from that grammar.

  
A string grammar is a 4-tuple G = (N, Σ, P, S): N = non-terminals (variables), Σ = terminals (constants, the primitives), P = productions (rewriting rules), S = starting symbol.

  
Example: N = {S, A, B}, Σ = {a, b, c}, P = {S → aA, A → bA, A → bB, B → c}. The primitives are a (left end), b (a short straight segment) and c (right end) of an object's pruned skeleton. This grammar generates only strings of the form abⁿc (n ≥ 1).

  
Note: the last production is B → c with a lower-case c, because c is a terminal. Once it is applied no non-terminals remain and the derivation ends.

14.2 Matching shape numbers

  
Like the minimum-distance idea, but for region boundaries described by shape numbers.

  
Freeman 4-direction chain code: 0 = right, 1 = up, 2 = left, 3 = down.

  
    
    
  1. Write the chain code of the boundary.
    2. 
    
  2. First difference: for each element, (current − previous) mod 4. The first element is compared with the last (the boundary is closed). Example: 2 − 3 = −1, and −1 mod 4 = 3.
    3. 
    
  3. Shape number: rotate the difference cyclically until it forms the smallest number.
    4. 
    
  4. Order n = number of digits in the shape number.
    5. 
  

  
The difference makes the code independent of rotation, and choosing the smallest rotation makes it independent of the starting point.

  

    
    Presets:
    
    
    
    
  

  

    
    

  


  
Degree of similarity k and distance D

  
Two shapes a and b have degree of similarity k if their shape numbers agree for every order 4, 6, 8, …, k and differ for k + 2, k + 4, …. The distance is D(a, b) = 1 / k. It satisfies D ≥ 0, D = 0 only if a = b, and D(a, c) ≤ max[D(a, b), D(b, c)]. Higher k (lower D) means more similar.

  
Example: find the closest match to shape f among shapes a to e. Pick two shapes, or press the button.

14.3 String matching

  
Code two region boundaries as strings a = a₁a₂…aₙ and b = b₁b₂…bm. Let α = number of positions where the symbols match. Then the number of mismatches is
  β = max(|a|, |b|) − α, and the similarity is R = α / β. If the strings are identical, β = 0 and R is infinite. Larger R means more similar.
